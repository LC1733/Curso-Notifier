MOD 01

¿Qué es VeriFire Tools?

El software oficial de programación, diagnóstico y mantenimiento de paneles NOTIFIER

VeriFire Tools (VFT) es la plataforma de software de Honeywell NOTIFIER para Windows que permite crear, editar, transferir y diagnosticar la base de datos de programación de los paneles NFS2-640, NFS2-3030, AFP y la familia completa de paneles NOTIFIER.

Sin VeriFire Tools no es posible programar un panel NOTIFIER moderno. Toda la lógica del sistema — qué hace el panel cuando un detector activa, qué sirenas suenan, qué módulos se disparan — se define aquí y se descarga al panel.

VeriFire Tools NO es un simulador. Las bases de datos creadas se transfieren directamente al panel mediante cable USB o RS-232. Un error de programación en VFT se convierte en un error real en el sistema instalado.

MOD 03

Crear Nueva Base de Datos

Flujo correcto desde archivo en blanco hasta panel configurado

01

Crear archivo nuevo

Ir a File → New. VeriFire solicita seleccionar el modelo del panel. Elegir el modelo exacto instalado — NFS2-640, NFS2-3030, etc. Un modelo incorrecto genera errores de transferencia.

02

Configurar Panel Identity

En Panel Configuration → System Settings definir: nombre del panel, nombre del sitio, nivel de contraseña, y si el panel pertenece a una red NFN asignar el Node ID único.

Panel Label: Nombre descriptivo — "Panel_Piso3_Norte". Sin espacios, usar guion bajo.
NFN Node ID: Del 1 al 103. Cada panel en la red debe tener ID único. Si es panel standalone, dejar en 01.
Password: Configurar contraseñas Level 1 (operador) y Level 2 (instalador). Documentar y guardar en lugar seguro.
03

Configurar lazos SLC

En SLC Loop 1 y SLC Loop 2 seleccionar la clase del circuito: Class A (Style 6) para proyectos industriales o Class B (Style 4) para proyectos estándar.

04

Guardar el archivo

Usar extensión .vfd. Nombrar el archivo con formato claro: PROYECTO_PANEL_FECHA.vfd. Ejemplo: MinaNorte_PanelMain_20260815.vfd. Mantener historial de versiones.

Nunca trabajar directamente sobre la base de datos activa de un panel en operación. Siempre hacer Upload primero para obtener la versión actual, guardar una copia de respaldo y trabajar sobre la copia.

Cada dispositivo requiere tres datos mínimos:

Tipo de dispositivo (Device Type) — Debe coincidir exactamente con el modelo físico instalado. Un detector NFXI-PHOTO programado como NFXI-HFS (calor) responderá de forma incorrecta.
Dirección (Address) — Debe coincidir con la dirección física configurada en el dispositivo (mediante DIP switches o programador de direcciones). La dirección errónea hace que el panel no reconozca el dispositivo.
Etiqueta (Label) — Descripción clara de la ubicación física. Máximo 40 caracteres. Ejemplo: DET-FOTO-PISO3-SALA-B. Esta etiqueta aparece en el display del panel durante una alarma.
Zona (Zone) — Asignar el dispositivo a la zona de detección correspondiente. La zona agrupa dispositivos por área geográfica o función.
Alarm Verification — Para detectores fotoeléctricos en ambientes con polvo o vapor, activar verificación de 10–30 segundos para reducir falsas alarmas.
Convención de etiquetas recomendada:
TIPO-TECNOLOGÍA-PISO-ÁREA-NÚMERO

Ejemplos: DET-FOTO-P3-SALA-B · MOD-FRM-P1-HVAC-01 · MAN-PULL-P2-EXIT-N

Una etiqueta bien hecha permite que cualquier técnico encuentre el dispositivo en campo sin planos.
MOD 05

Zonas y Grupos

Organización lógica del sistema — cómo agrupar dispositivos para el control

Las zonas agrupan dispositivos de detección por área geográfica o función. Cuando cualquier dispositivo de una zona activa, el panel reporta la zona completa en su display. Las zonas son la base sobre la cual se construye la lógica Cause & Effect.

El NFS2-640 soporta hasta 250 zonas. El NFS2-3030 hasta 3.000 zonas.

ZonaNombreDispositivos incluidosTipo
Z-001 Piso 1 — Lobby y accesos DET 001–015, MAN 016, MAN 017 Alarm
Z-002 Piso 1 — Sala de servidores DET 018–025 (BEAM) Alarm
Z-003 Piso 3 — Oficinas norte DET 027–045 Alarm
Z-010 Válvulas sprinkler — Piso 1 MMX 100–103 (water flow) Supervisory
Z-020 HVAC — Control general FCM 110–115 Control
Los dispositivos de tipo Supervisory (válvulas, presión) se programan en zonas separadas de las zonas de alarma. Esto permite que el panel maneje cada tipo de señal con su propio protocolo de respuesta.
MOD 06

Lógica Cause & Effect

El cerebro del sistema — definir qué hace el panel cuando activa un dispositivo

La lógica Cause & Effect (C&E) es la programación que define exactamente qué acciones toma el panel cuando ocurre un evento. Es la parte más crítica de la programación — un C&E mal configurado puede hacer que el sistema no responda en una emergencia real.

En VeriFire Tools, el C&E se configura en una matriz de causa-acción: cada fila es una causa (zona o dispositivo que activa), cada columna es una acción (NAC, módulo, transmisión).

Ejemplos de reglas C&E típicas en proyectos industriales:

CAUSAACCIÓNDescripción
Z-001 ALARM NAC-1 + NAC-2 ON Activar todas las sirenas del edificio si alarma en Piso 1
Z-002 ALARM FCM-029 ON Apagar HVAC de sala de servidores para contener humo
Z-001 OR Z-002 RELAY-1 ON Liberar puertas magnéticas de emergencia en Piso 1
ANY ALARM TRANSMIT Enviar señal a central de monitoreo remoto
Z-002 ALARM + 30 sec FRM-028 ON Activar sistema de supresión sala servidores con retardo de 30 seg
Z-010 SUPERVISORY TRANSMIT (SUP) Reportar válvula cerrada a central — solo supervisory, no alarma
El C&E con retardo temporal (timers) es especialmente crítico en sistemas de supresión. Un timer mal configurado puede activar la supresión con personas adentro o no activarla cuando es necesario. Siempre verificar timers en campo durante el Walk Test.
MOD 07

Transferencia y Diagnóstico

Download al panel, verificación y lectura de estado en tiempo real

01

Conectar PC al panel

Conectar cable USB al puerto frontal del panel (NFS2-640) o RS-232/USB al puerto de programación. En VFT ir a Panel → Communications → Select Port y elegir el COM correcto. Verificar que VFT detecta el modelo del panel.

02

Validar la base de datos antes del download

Usar Tools → Validate Database. VFT revisa errores: direcciones duplicadas, tipos de dispositivo inválidos, zonas sin dispositivos, C&E sin acciones. Resolver todos los errores antes de descargar.

03

Ejecutar Download

Ir a Download → Full Download. El proceso toma entre 2 y 15 minutos según el tamaño de la base de datos. El panel se reinicia automáticamente al finalizar. No desconectar durante la transferencia.

Full Download: Reemplaza toda la base de datos del panel. Usar para instalación nueva o cambios mayores.
Partial Download: Solo descarga los elementos modificados. Más rápido, pero requiere verificar qué cambió.
04

Verificar con Upload + Compare

Después del download, usar Upload → Compare. VFT lee la base de datos del panel y la compara con la del PC. Si hay diferencias, lo reporta. Cero diferencias = download exitoso.

05

Monitor de estado en tiempo real

Con el panel conectado, usar Tools → Status Monitor. Muestra el estado actual de cada dispositivo del SLC: NORMAL, ALARM, TROUBLE, MISSING. Herramienta esencial para diagnóstico de fallas sin operar el panel físicamente.

06

Leer historial de eventos

Usar Upload → History. El panel almacena los últimos eventos con fecha, hora, tipo y dispositivo. Imprescindible para investigar incidentes, falsas alarmas o inspecciones de mantenimiento.
